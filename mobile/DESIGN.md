# Navigator Mobile design and scope

Navigator Mobile is a separate Expo app. It shares the product identity and backend services with Navigator web and desktop. It does not replace those clients or their interfaces.

## Current goal

Build a native iOS and Android browsing and playback experience, with source-owned React Native Reusables components. Implement the mobile web design as a visual reference, not as a WebView. Prioritize the centered Home hero and media cards, native navigation and sheets, title details, library and playback.

Do not implement Ask Navigator, scene-assistant cards, AI provider setup or chat in this phase. Leave the vibrant-color extraction, persistent Aurora and decorative gradient background out. Use the existing neutral Navigator light/dark palette and Sunghyun Sans. Gradients for artwork legibility and progressive blur masks are still in scope.

## Home

- Full-bleed hero artwork with centered title wordmark (or centered text fallback), rating, year and runtime when available (with the same fact icons as web), and genres with a tag icon and a compact primary action (white in dark mode, black in light mode). The fully rounded View button uses medium weight and has a trailing arrow-right icon and opens the title page. Playback is not implemented yet. Keep at least 24 points of visible clearance between the View action and the compact carousel pill. Inactive dots are circular (6 × 6 points, rounded to equal device pixels); the selected dot is a capsule. The carousel preserves a 44-point tall touch area. A horizontal pan blends the outgoing and incoming artwork in direct proportion to the finger travel. The wordmark, metadata and dot weights follow the same shared progress. A slow short pull returns to the current title without feedback. A distance or velocity commit settles with a damped spring and one selection tick. Use iOS selection feedback and Android Segment Tick (Clock Tick on older versions), not repeated vibration. Reduced Motion preserves the finger-linked opacity but skips the automatic settle motion.
- Progressive blur in the lower image area: several independently blurred versions of the same artwork, each with a gradient mask and a larger radius toward the bottom. This avoids private system filters and blurring unrelated UI. Fade into the theme background below the centered content. Keep the final artwork pixels inside the hero, with a solid theme-color edge so no separator line appears above the catalog. Preserve readable text and the original artwork aspect ratio.
- Native horizontal rails of 2:3 posters, rounded corners, one or two readable title lines, and muted year or release metadata. Use cached Expo Image artwork, fallback for failed images and subtle press scale instead of hover. Include Continue Watching only after account data is available.
- Use Cinemeta directly as the default for live Home catalogs, search and title metadata. TMDB is an optional selection in Settings and uses the Navigator metadata service. Persist the choice on the device. Do not include sample catalog data in the app or device previews.
- Full movie, TV and individual episode details are separate native stack pages. They include a back action (system Liquid Glass on iOS, native blur on Android), full-bleed backdrop or episode still, centered wordmark in both themes, metadata chips for release date, seasons or runtime, source-labeled IMDb/TMDB score and age certification when supplied. No generic Movie/TV Show badge. Missing age certification can be supplemented by the configured TMDB service without changing the catalog provider. Place the Play pill and Shuffle/Like actions above the compact synopsis. Like is local-only; Shuffle opens a real random episode. Play reports that the native player is not connected yet. Lay out genres as wrapping chips. Use a season-selection bottom sheet and a horizontal 16:9 episode rail with a teal selected/focus ring and shadow. Do not duplicate the title page in a quick-actions sheet. Reserve sheets for meaningful contextual actions. Use Gorhom Bottom Sheet with Gesture Handler and Reanimated, plain legible theme surfaces and an optional public-API blur background on supported devices. Use iOS native glass only for compact floating controls.

## Native navigation

- Home, Search and Settings are native bottom tabs. iOS 26 uses the system Liquid Glass tab bar. Android uses the native Material tab bar. Title pages open above the tabs on the root stack.
- Match the current web phone detail layout: no separate poster block, full-bleed poster only as a fallback when backdrop art is missing.

- iOS uses Expo Router’s standard native `Stack` with default interactive back gestures. Android uses the SDK 56 `ExperimentalStack` prototype, the documented native gamma stack with predictive back support. The manifest opts into predictive back on Android 13 and later. No WebView or custom JavaScript back-swipe handler is used.
- The Android experimental stack is an alpha API. It does not support stack-based sheets or custom navigation bar options, so use the separate Gorhom action sheet. Verify native Android gesture navigation and committed edge back in standalone CI; Expo Go does not apply the app’s Android manifest. Keep the experimental stack under review as Expo upgrades.
- References: [Expo Router Stack](https://docs.expo.dev/router/advanced/stack/), [SDK 56 ExperimentalStack](https://docs.expo.dev/versions/v56.0.0/sdk/router/experimental-stack/), [Android predictive back](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture).

## Iteration and verification

Keep the component preview accessible at `/design-system`. Use Expo Fast Refresh on a compatible connected phone when available for rapid edits. CI builds the standalone native app on GitHub-hosted runners and captures actual iPhone, iPad and Android screenshots, including the hero, rails, movie and TV detail pages, tabs, light/dark modes and increased Android text size. Use live Cinemeta data for device previews. Use isolated mock responses in unit tests only. Keep screenshots as GitHub artifacts and share selected PNG files with the user for visual review. Compare native screenshots against the existing web design and check real interaction on devices where hardware behavior matters.

The following work remains deliberately out of scope: Ask Navigator, vibrant color extraction, Aurora, decorative gradient backgrounds, physical-device HDR tuning, and a web or desktop redesign.
