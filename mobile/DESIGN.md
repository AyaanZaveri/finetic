# Navigator Mobile design and scope

Navigator Mobile is a separate Expo app. It shares the product identity with Navigator web and desktop. It uses Cinemeta and Stremio directly and does not depend on the Navigator server.

## Current goal

Build a native iOS and Android browsing and playback experience, with source-owned React Native Reusables components. Implement the mobile web design as a visual reference, not as a WebView. Prioritize the centered Home hero and media cards, native navigation and sheets, title details, library and playback.

Do not implement Ask Navigator, scene-assistant cards, AI provider setup or chat in this phase. Leave the vibrant-color extraction, persistent Aurora and decorative gradient background out. Use the existing neutral Navigator light/dark palette and Sunghyun Sans. Gradients for artwork legibility and progressive blur masks are still in scope.

## Touch actions

Do not underline buttons or links in the Expo app. For low-emphasis text actions, use semibold text with clear contrast, visible press feedback and a 48-point touch target. Keep the semantic button or link role.

## Home

- Full-bleed hero artwork with centered title wordmark (or centered text fallback), one quiet metadata line for the media type, up to two genres and age certification when supplied. Keep the release year, runtime and numeric ratings on the detail page. The View action shares the Play button’s 48-point minimum height and 17-point semibold text, with a trailing 20-point arrow-right icon and 128-point minimum width. It opens the title page. On iOS, share the interactive native Liquid Glass button material used by Shuffle and Like, but use a contrasting glass appearance and tint for the primary CTA: white glass with dark text and arrow in dark mode, and dark glass with white text and arrow in light mode. Use a matching solid fallback. On Android, use the solid foreground fill for clear contrast. Keep Play solid on both platforms. Playback is not implemented yet. Keep 18 points of visible clearance above and below the View action so the metadata and compact carousel pill are evenly spaced. Inactive dots are circular (6 × 6 points, rounded to equal device pixels); the selected dot is a capsule. The carousel preserves a 44-point tall touch area. A horizontal pan blends the outgoing and incoming artwork in direct proportion to the finger travel. The wordmark, metadata and dot weights follow the same shared progress. A slow short pull returns to the current title without feedback. A distance or velocity commit settles with a damped spring and one selection tick. Use iOS selection feedback and Android Segment Tick (Clock Tick on older versions), not repeated vibration. Reduced Motion preserves the finger-linked opacity but skips the automatic settle motion. Respect a persisted app-wide Haptic feedback preference in Settings; when disabled, no app-triggered haptics dispatch.
- Progressive blur in the lower image area: several independently blurred versions of the same artwork, each with a gradient mask and a larger radius toward the bottom. This avoids private system filters and blurring unrelated UI. Fade into the theme background below the centered content. Keep the final artwork pixels inside the hero, with a solid theme-color edge so no separator line appears above the catalog. Preserve readable text and the original artwork aspect ratio. In light mode, add a stationary top scrim above the composed artwork on Home and all detail pages. Keep at least 60% white through the top safe-area inset, fading to transparent 72 points below it. This protects dark system icons even over black artwork without adding a hard cutoff or whitening the whole image. Dark mode keeps its existing artwork treatment. See [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Apple color guidance](https://developer.apple.com/design/human-interface-guidelines/color) and [Android edge-to-edge guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge).
- Native horizontal rails of 2:3 posters, rounded corners, one or two readable title lines, and muted year or release metadata. Use cached Expo Image artwork, fallback for failed images and subtle press scale instead of hover. Include Continue Watching only after account data is available.
- Use Cinemeta directly for live Home catalogs, search and title metadata. Do not include sample catalog data in the app or device previews.
- Full movie, TV and individual episode details are separate native stack pages. They include a back action (system Liquid Glass on iOS, native blur on Android), full-bleed backdrop or episode still, centered wordmark in both themes, metadata chips for release date, seasons or runtime, source-labeled IMDb score and age certification when Cinemeta supplies them. Omit missing metadata and the generic Movie/TV Show badge. Place the Play pill and Shuffle/Like actions above the compact synopsis. Like is local-only; Shuffle opens a real random episode. Play opens the stream selector. Lay out genres as wrapping chips. Use a season-selection bottom sheet and a horizontal 16:9 episode rail with a teal selected/focus ring and shadow. Do not duplicate the title page in a quick-actions sheet. Reserve sheets for meaningful contextual actions. Use Gorhom Bottom Sheet with Gesture Handler and Reanimated, plain legible theme surfaces and an optional public-API blur background on supported devices. Use iOS native glass only for compact floating controls.

## Stream selector

- Signed-out Play opens Sign in, not the stream drawer. Lead with the Sign in with Stremio button and brand mark, then a lowercase “or” divider in muted 12-point regular type, email and password, and the email Sign in button. The first action names the task, so omit the visible heading. Announce “Sign in” for screen readers. Do not show the title name, episode, or Streams heading. Close the form after successful sign-in.
- Match the Play and View buttons: use the shared pill shape, 48-point minimum height, and 17-point semibold labels. Use a solid dark fill in light mode and a solid light fill in dark mode for Sign in with Stremio. Give email Sign in the quieter filled style. Use a solid surface for the form so artwork does not show through its controls. Keep the stream and season drawers unchanged.
- On compact layouts, use a content-sized Gorhom drawer with one bottom safe-area inset, 16 points of padding after the last control, and a 440-point maximum width. Keep an 8-point gap above the software keyboard. At 720 points of safe width or more, use a centered form dialog up to 520 points wide. Keep both forms scrollable when the keyboard or larger text limits space. Do not open the keyboard automatically. Use the backdrop, Android Back, or accessibility escape to dismiss either form. The compact drawer also supports dragging. Do not add a visible close button.
- Signed-in Play opens the taller stream drawer for the movie, current episode, or selected episode on the series overview. Show episode coordinates there. Disable series Play until an episode is available. The drawer selects a stream locally and does not start the native player.
- Show the add-on results as they arrive, in provider order. Use a virtualized list with the same information hierarchy as the web selector: quality and source first, then provider details, filename and size. Combine text search, an add-on filter and quality filters. Within each quality group, match any selected option. Across groups, require all selected groups to match. Keep provider notices readable without offering them as playable streams.
- Use Stremio's official device-link flow for the provider button and direct Stremio authentication for the email form. Store only the session key in iOS Keychain or Android Keystore through Expo SecureStore. Send the key only to Stremio. Request streams directly from applicable add-ons without the Stremio key or account cookies. Sign out clears the local key. Cancel requests when the drawer closes and keep errors and retries in the drawer.

## Current visual polish batch

- Search uses a filled, fully rounded field with a plain clear icon and vertically centered content. Use native Liquid Glass for the iOS surface where available, with a quiet solid fallback. Use the native iOS single-line text field and system font metrics for vertical alignment of both the prompt and entered text. Remove the redundant results heading. A full-width three-segment filter slides its selected background with one selection haptic per change. Keep labels on one line and use three poster columns when width and text size permit.
- Use a stable, bottom-aligned wordmark slot with a 112-point minimum height on phones and 136 on wide windows. Give the wordmark and short metadata summary a 12-point gap on phones and 16 on wide windows. Use a 12-point gap before the tablet synopsis and 16 to 20 points after the carousel touch area. Separate hero facts with a bold middle dot, one point larger than the 14–15-point medium-weight text, with a one-third-em space on each side and quieter contrast. Let metadata wrap at larger text sizes instead of clipping it. Keep visible gaps around View balanced, dots circular and the carousel compact. Let the native glass shadow fade beyond the artwork edge rather than clip it. Load the unblurred image and its progressive blur masks together, and keep the same artwork and mask quality throughout a swipe. Do not expose the sharp backdrop while its blur layers load. Use Liquid Glass for compact iOS floating controls where contrast is sufficient; keep primary actions highly legible.
- Keep title artwork fully visible, scale the wordmark to fit, measure transparent margins and use an 18-point optical gap on phones (24 on tablets), use the actual IMDb wordmark asset, align genre/credit labels and values, and keep real metadata visible when available. Use larger semibold Play text and native glass secondary actions on supported iOS devices. Use compact 24-point minimum-height metadata and genre chips with 12-point text, 8-point horizontal and 2-point vertical padding. Headline facts use noninteractive native glass on supported iOS devices, with solid fallback; genres and Android facts use quiet filled surfaces rather than blurring an already solid page. Do not manufacture missing metadata. Share title details and predecoded wordmarks across Hero, Search and detail routes. Prefetch active/adjacent heroes and the first three results of each visible catalog or Search list, with bounded concurrency; avoid repeated network work.
- Give catalog headings and poster rails a 12-point gap. Keep the Home hero full-bleed while reserving enough scroll clearance below the last rail for the floating iOS tab bar. Use the native Android bottom inset and automatic adjustment for ordinary iOS scroll views. Prefer filled surfaces, spacing and contrast over decorative borders. Use no permanent outline on poster cards or the season picker. The season trigger is a compact 36-point filled pill inside a 48-point touch target, with Liquid Glass on supported iOS devices. Keep a visible focus/selection ring only where it communicates state.
- Use a native iOS switch for the Haptic feedback preference. The detached season sheet has rounded corners and 12-point side margins. Use the system bottom safe-area inset once, with an 8-point minimum gap on phones (12 on wide windows); do not add a second full bottom gutter. Use one content-sized detent (bounded by available height) to keep all four corners visible, with about 16 points of internal bottom padding after the final row. A dim backdrop and native iOS Liquid Glass or Android public-API blur separate the floating surface from the page; use a legible solid fallback. Its iOS modal must be accessible above the native stack. See [Apple sheet guidance](https://developer.apple.com/design/human-interface-guidelines/sheets) and [Android edge-to-edge insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge). The specific 8- and 12-point offsets are Navigator design choices.
- Keep the design and animation controls source-owned. Consult official [Expo skills](https://docs.expo.dev/skills/) for native UI, safe-area handling, navigation, motion and development builds. The official skills are linked locally in `.agents/skills/` and are not bundled in the app.

## Native navigation

- Home, Search and Settings are native bottom tabs. iOS 26 uses the system Liquid Glass tab bar. Android uses the native Material tab bar. Title pages open above the tabs on the root stack.
- Match the current web phone detail layout: no separate poster block, full-bleed poster only as a fallback when backdrop art is missing.

- iOS uses Expo Router’s standard native `Stack` with default interactive back gestures. Android uses the SDK 56 `ExperimentalStack` prototype, the documented native gamma stack with predictive back support. The manifest opts into predictive back on Android 13 and later. No WebView or custom JavaScript back-swipe handler is used.
- The Android experimental stack is an alpha API. It does not support stack-based sheets or custom navigation bar options, so use the separate Gorhom action sheet. Verify native Android gesture navigation and committed edge back in standalone CI; Expo Go does not apply the app’s Android manifest. Keep the experimental stack under review as Expo upgrades.
- References: [Expo Router Stack](https://docs.expo.dev/router/advanced/stack/), [SDK 56 ExperimentalStack](https://docs.expo.dev/versions/v56.0.0/sdk/router/experimental-stack/), [Android predictive back](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture).

## Adaptive iPad and Android tablet layout

- The system iPadOS tab bar sits at the top and uses native Liquid Glass on iPadOS 26. Navigator has only three main sections, so keep the compact tab bar rather than add a permanent sidebar. iPhone retains the system bottom bar. Use [Apple's tab bar guidance](https://developer.apple.com/design/human-interface-guidelines/tab-bars) and [Apple TV on iPad](https://support.apple.com/en-am/guide/ipad/ipad431a7951/ipados) as layout references, not as a component template.
- Base responsive layout on available window width, not physical device identity. Keep phone and narrow split-view content centered. At roomy widths (768 points for Home, 720 for detail columns), put title artwork, facts, a short synopsis and the View action on the leading edge; keep the carousel indicators centered and the artwork full-bleed with a gradual fade. Scale the wide Home hero to approximately 68% of the available height in landscape, and around half the display height in portrait, with a 740-point maximum to retain a visible preview of the catalog. Align detail facts, Play, and synopsis with the title wordmark. Do not repeat a poster beside the detail content; use the backdrop or a full-bleed poster fallback. Limit detail text to 680 points while episode and cast rails can use the available width. Use 24 to 32-point gutters, bounded text widths and adaptive poster grids. Do not stretch the phone UI across the full display.
- The [Android window size classes](https://developer.android.com/develop/ui/views/layout/window-size-classes) define compact below 600dp, medium from 600dp, expanded from 840dp and large from 1200dp. Treat these as design references for responsive content, and keep the existing native tab navigation until a supported adaptive native rail is available. Test rotation and split-view widths. Keep shared control targets at least 48 points/dp and preserve text scaling.
- Use a 4-point spacing unit with an 8-point primary rhythm. Use 16-point phone gutters, 24-point medium-window gutters and 32-point wide-window gutters. Keep 48-point primary controls; use typography roles rather than stretching phone font sizes. Standard text remains 14 to 17 points with larger headings and dynamic type.
- The iPad preview reuses the universal iOS development client and captures portrait and landscape Home, Search and detail views on an actual iPad simulator in an independent GitHub Actions job. No separate native build is required on a cache hit.

## Iteration and verification

Keep the component preview accessible at `/design-system`. Use the custom Expo development client and Fast Refresh for rapid UI iteration. The development CI workflow restores fingerprint-matched native binaries and serves the current source through Metro; it records live UI screenshots and videos. The standalone release CI workflow builds the native app only for final verification on GitHub-hosted runners and captures actual iPhone, iPad and Android screenshots, including the hero, rails, movie and TV detail pages, tabs, light/dark modes and increased Android text size. Use live Cinemeta data for device previews. Use isolated mock responses in unit tests only. Keep screenshots as GitHub artifacts and share selected PNG files with the user for visual review. Compare native screenshots against the existing web design and check real interaction on devices where hardware behavior matters.

The following work remains deliberately out of scope: Ask Navigator, vibrant color extraction, Aurora, decorative gradient backgrounds, physical-device HDR tuning, and a web or desktop redesign.
